# Contributing to SoftPulze

Thanks for helping improve SoftPulze's open-source projects. This guide applies to every public repository in the [thesoftpulze](https://github.com/thesoftpulze) organization unless that repository has its own `CONTRIBUTING.md`.

## Before you start

- Read our [Code of Conduct](CODE_OF_CONDUCT.md).
- Search existing issues and pull requests to avoid duplicates.
- For anything larger than a small fix, open an issue first so we can agree on the approach.
- Report security problems privately, as described in [SECURITY.md](SECURITY.md), not in a public issue.

## Reporting bugs

Open an issue with the **Bug report** template. Include:

- what you expected and what happened instead
- steps to reproduce, ideally a minimal example
- versions (PHP, Laravel, Node, package version, OS) where relevant

## Suggesting features

Open an issue with the **Feature request** template. Describe the problem you're trying to solve before the solution you have in mind.

## Pull requests

1. Fork the repository and create a branch from `main` (for example `fix/lookup-pagination`).
2. Keep each pull request focused on one change.
3. Follow the existing code style. Run the project's formatter, linter and tests before pushing.
4. Add or update tests and documentation for any change in behavior.
5. Write clear commit messages in the imperative mood ("Add X", "Fix Y").
6. Fill in the pull request template and link the related issue (for example `Closes #12`).

A maintainer will review your pull request. We may ask for changes before merging.
